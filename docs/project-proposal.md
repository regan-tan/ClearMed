# ClearMed Study

## 1. Project Overview

Medical students commonly use question banks with fixed explanations. ClearMed Study investigates how those explanations can become interactive through a retrieval-grounded conversational tutor. The project evaluates both medical question answering and evidence retrieval for follow-up responses. It is for educational use only.

## 2. Research Questions

- RQ1: Does LoRA fine-tuning of FLAN-T5 improve medical MCQ performance compared with classical and scratch-trained NLP baselines?
- RQ2: Can retrieval-grounded generation improve follow-up reliability and reduce unsupported medical claims?
- RQ3: How does embedding-model choice affect retrieval effectiveness for medical follow-up questions?
- RQ4: Does stronger retrieval lead to more accurate and better-grounded conversational responses?

## 3. Dataset

The primary dataset is MedMCQA, which includes MCQ questions, answer options, correct answers, explanations, medical subjects, and topics. Official train, validation, and test separation will be preserved. Only training examples and explanations may form the retrieval corpus; validation and test explanations must never be indexed, preventing gold-answer leakage during evaluation.

## 4. Part I — Medical QA and Conversational Tutoring

### 4.1 Models

- **TF-IDF baseline:** a lightweight classical NLP reference point.
- **Scratch Seq2Seq:** an LSTM/GRU encoder-decoder with attention, used to compare learning without pretrained language representations.
- **FLAN-T5 + LoRA:** the main proposed pretrained encoder-decoder model, fine-tuned efficiently with LoRA.

### 4.2 Training Workflow

```text
local development
  → small FLAN-T5 smoke test
  → school GPU cluster
  → LoRA fine-tuning
  → save adapter + predictions + metrics
  → local evaluation
```

Only the LoRA adapter and experimental outputs need to be copied back locally.

### 4.3 Conversational Follow-Up

```text
original exam question + student follow-up
  → construct retrieval query
  → retrieve relevant training evidence
  → check whether evidence is sufficient

YES → top-k evidence → FLAN-T5 + LoRA → grounded answer
NO  → fixed deterministic fallback
```

The fallback is application-level logic and is not generated by FLAN-T5.

## 5. Part II — Embedding Model Comparison

Part II holds the remaining system constant and compares three embedding approaches:

- **MiniLM** (`sentence-transformers/all-MiniLM-L6-v2`): a general-purpose semantic model.
- **E5-base-v2** (`intfloat/e5-base-v2`): a retrieval-specialised query/passage model.
- **BioLORD-2023** (`FremyCompany/BioLORD-2023`): a biomedical-domain representation model.

The retrieval corpus, document representation, query construction, cosine-similarity ranking, retrieval depths, generator, generation prompt, and evaluation set are controlled variables.

### 5.1 Retrieval Pipeline

```text
context-rich follow-up query
  → embedding model
  → query vector
  → cosine similarity
  → rank MedMCQA training passages
  → top-k evidence
```

The same depths are used for each model: k = 1, k = 3, and k = 5. Retrieval depth k is the number of highest-ranked passages considered or retrieved.

## 6. Evaluation

Part I measures answer accuracy, subject-level accuracy, malformed-output rate, ROUGE-L, BERTScore, and qualitative error analysis.

Part II measures Recall@1, Recall@3, Recall@5, and MRR. Downstream evaluation considers correctness, groundedness, unsupported claims, fallback behaviour, and multi-turn consistency.

Retrieval must be evaluated independently from FLAN-T5 generation. Raw cosine scores are not assumed comparable across embedding models. If fallback thresholds are used, each model requires separate validation calibration. No embedding model is assumed to win before experimentation.

## 7. Overall System Architecture

```text
MedMCQA → preprocessing → Part I model comparison → QA evaluation
  → answer + explanation → student follow-up → Part II embedding comparison
  → top-k evidence → sufficient evidence decision
  → grounded FLAN-T5 answer OR deterministic fallback
```

## 8. Scope and Limitations

ClearMed is for educational use only, not diagnosis, treatment, or clinical decision support. Dataset-specific performance may not generalise, and automatic metrics do not prove medical correctness. Retrieval quality depends on the available corpus evidence. Locally runnable models are deliberately selected for reproducibility and feasibility.
